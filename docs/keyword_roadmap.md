# Keyword Roadmap: from today's matrix to every keyword real

Written 2026-11-13 from `docs/keyword_matrix.md` (148 registered keywords: 59 REAL, 16 PARTIAL, 11 SEAM, 62 below SEAM; 20 rows with no evidence gap) and `Audit_keywords.md`.

This file says **in what order** keywords move and **what each move needs**. It does not say how far any keyword has got: that is the matrix, regenerated by `pilot run tools/keyword_matrix/main.pilot`. Never record progress here; record it in the matrix's hand columns and in `selfhost/gate/ledger/wiring.pilot`.

---

## 1. The end state

The roadmap is finished when **every keyword in the registry (`stdlib/core/keywords.pilot`) has a matrix row with**:

- Verdict `REAL`: it does what its registry description says, shown by runs;
- Evidence gaps `none`: a grammar binding, a named passing program, a named `err_*` program, a wiring ledger row, the same result on `pilot test`, `pilot test --ir` and `pilot test --emit c`, and no open known bug;
- a ledger row at `WIRED`. Only the project owner raises it to `COMPLETE`.

A keyword never leaves this roadmap by being dropped quietly. It can leave the registry only when the owner decides that it should not be a keyword (section 4). Then the registry, the matrix and this file all change in the same commit.

---

## 2. How progress is measured

Each keyword climbs one ladder. A session's result is the rungs it moved, not whether it reached the top.

| Rung | Verdicts in the matrix today | What it means |
|---|---|---|
| 0. False | UNBOUND, MISPARSED, IGNORED, SIMULATED, BROKEN | The registry claims something the language does not do, or does something else silently. |
| 1. Honest | SEAM | Bound to grammar. Every use either works or stops with a diagnostic or `SEAM001` naming what is missing. Nothing pretends. |
| 2. Partial | PARTIAL | Some of the registry's promise works on all engines; the rest stops honestly. |
| 3. Real | REAL with gaps | The promise works; some evidence is missing. |
| 4. Done | REAL, gaps `none`, ledger `WIRED` | The end state above. |

Rules for the ladder:

- **Rows only move up.** A change that moves a row down (a fake found, a bug found) records why in the Notes column and files the known bug or ledger row in the same change. That is still progress, because the matrix is now true.
- **Rung 1 is worth reaching early.** A keyword at SEAM cannot mislead the next agent. A keyword at rung 0 can.
- **The matrix decides.** If a session's report and the matrix disagree, run the programs and fix whichever is wrong.

## 3. How to ask for keyword work

Wording matters: "make X work" or "complete the keywords" sets an end state, and when the end state cannot be reached the easy way out is a fake. Ask for movement, give a measure, and say that stopping at a named blocker is a good result.

**Template:**

> Advance the keywords of phase K*n* in `docs/keyword_roadmap.md`: *[list, or "the next three in the list"]*. For each, move its matrix row as far up the ladder as it honestly goes. First write the acceptance programs from the registry description, with expected output worked by hand. Where a keyword cannot go further, leave a registered seam and name what blocks it. Regenerate the matrix, then report where each keyword ended, blocked ones first.

**Examples:**

- "Advance `struct` and `op` in phase K1: equality of two equal records (W4) and a declared `op ==`. Report where each ended."
- "Bring the phase K0 SIMULATED keywords up to rung 1: replace each fake rule with a seam, add ledger rows, add an `err_*` program per keyword. No new runtime."
- "Triage phase K7: for each keyword, say which runtime pieces exist, which are missing (name them), and what the smallest real first step is. Change no code."

**Avoid:** "complete", "all", "make X work", and "fix X" for a missing feature ("fix" suits a bug with a repro). **Prefer:** "advance", "close the gaps", "as far as it honestly goes", "until blocked", "report where it stopped".

**One phase, a few keywords per session.** Smaller scope leaves less pressure to cut corners and gives a reviewable diff.

## 4. Owner decisions that block keywords

These keywords cannot become real until the owner says what they mean. An agent reaching one of them stops at a seam and lists the question; it does not choose. The owner answers each one when its phase is reached (decided 2026-11-13), so an agent working on that phase asks it in its report, not before.

| # | Keywords | The question |
|---|---|---|
| D1 | `scope`, `enter`, `exit` | What enters a value: the `scope self { enter: .. exit: .. }` hooks of a type, a block form, or both? (Seam `lifecycle.scope_self` says this is undecided.) |
| D2 | `unit` | The registry says "Declares a standalone compilation unit"; the grammar binds dimensional literals (`250ms`, `64KB`). Which meaning stays? If dimensions, the description changes. |
| D3 | `module`, `pkg` | Two words for packaging. One keyword per responsibility (AGENTS.md section 2): keep both with distinct meanings, or retire one? |
| D4 | `call_quote_shallow`, `call_quote_deep`, `call_quote_abi`, `call_quote_signal`, `call_quote_dual`, `call_quote_plan`, `op_splat`, `op_pairs`, `op_expand`, `unquote` | **Decided 2026-11-13: Pair columns.** A symbolic form is the Pair of its readable twin, and the twin's row is its status. The nine named entries are deleted from the registry (`call` `!`, `splice` `!!`, `frame` `!&`, `sig` `!^`, `grad` `!@`, `plan` `!?`, `splat` `*`, `pairs` `**`, `flat` `*..` already carried those Pairs). `unquote` keeps its row with Pair `~`: `~x` has no readable twin bound, and its status follows the deep splice (seam `vm.call_quote`). |
| D5 | `asm`, `assembly` | No milestone schedules a per-target assembler. `assembly` is described as "an external linked assembly binary library" but is bound as an inline-language word. Pick each meaning and a milestone. |
| D6 | `actor` | Message-passing actors as their own model, or a library over M83's structured concurrency (`scope`, `task`, `chan`)? |
| D7 | `int` | "Compilation boundary": what is that boundary before packages exist (M48)? |
| D8 | `region` | `with arena a { .. }` (ledger F7) already owns scoped arenas. Is `region` a second spelling, or a distinct thing? |
| D9 | `bounded` | "buffer, channel, or loop execution": one keyword for three responsibilities. Which one? |
| D10 | `each` | Parameter form (`fn f(each x: T)`), prefix form (`f(each xs)`), or both? |
| D11 | `lvl` | What does a package's level (`pub lvl(N) pkg Name;`) mean? Every `stdlib/core` package is `lvl(Cfg.Tokens.ring_genesis)` (100) and user code at level 0 calls it, so it cannot be "the clearance needed to use this package" as it is for a function. Is it the clearance the package's code holds, a ceiling on what it may declare, or something else? Until then only a function's own `lvl(N)` is read (seam `lvl.clearance`). |

## 5. Rules for every phase

1. **Acceptance programs first.** Write them from the registry description before the code (AGENTS.md 9.1). Include at least one named passing program and one named `err_*` program, and work the expected output by hand in a comment.
2. **Real or seam, never in between.** Each piece of a keyword either works on all three engines or stops with a diagnostic or `SEAM001`. Add a known bug when two engines disagree.
3. **Move later, never out.** A keyword blocked by something a later phase builds moves to that phase, with a Notes entry naming the blocker. It does not leave the map.
4. **Update in the same change:** the matrix hand columns (then regenerate), the wiring ledger, the seam ledger and `docs/keyword_matrix.md` notes.
5. **A phase is finished** when every keyword it lists is at rung 4 or has moved to a later phase with its blocker named. Phases K5 to K10 may run in any order once their prerequisites are met.

## 7. The phases

### K0: Truth floor

**Goal.** No keyword stays at rung 0, and every REAL row gets its missing evidence. No new runtime is built in this phase: it is about making the language honest about what it does.

**Work:**
- **Fakes to seams.** Replace each of these rules with a seam or a diagnostic. Record the old behaviour as `SIMULATED` in the wiring ledger until the real feature lands. Write `err_*` programs that show the stop. Keywords: `await`, `spawn`, `atomic`, `sync`, `isolate`, `select`, `transaction`, `commit`, `rollback`, `savepoint`, `region`, `deadline`, `within`, `periodic`, and the `noalloc` block form. Also the rule words `on_missed` and `fallback` (audit 2.3).
- **Misreadings to diagnostics.** Each of these is accepted as something else today. It must instead be rejected with a code, or stop at a seam: `adapter`, `database`, `context`, `asm`, `assembly`, `extern`, `lib`, `async`, `each`, `open`, `export`, `lvl`.
- **Unbound to bound.** Each keyword with no grammar gets a binding whose every use reports a "not implemented yet" diagnostic naming its phase in this file. Its registry description is marked as a target. Keywords: `actor`, `state`, `timeout`, `bounded`, `priority`, `jitter`, `connect`, `order`, `ascending`, `descending`, `insert`, `into`, `values`, `update`, `delete`, `module`, `alignof`, `offsetof`, `fields_of`, `blueprint`, `cue`, `role`, `route`, `override`, `transition`, `unquote`, `macro`. Bound 2026-11-13 to receptor 40 (place 1: where a declaration or statement starts; place 2: as a query clause), `override` as an unbuilt modifier, and `alignof`, `offsetof`, `fields_of` as type queries; per D4 the nine symbolic-form names are Pair columns of their twins and `unquote` carries Pair `~`.
- **Evidence for REAL rows.** Close the gaps of every REAL row whose gaps are only evidence: named programs, ledger rows, a per-engine run. The matrix lists them; filter Verdict REAL whose Evidence gaps do not include `known bug open` or `an engine`.
- **Enforcement.** Build the check that AGENTS.md section 11 lists as not built. `pilot gate` should fail when a registered keyword has no binding, or when a row's verdict is below SEAM. Run it from the matrix tool's data so it can never disagree with the matrix.

**Exit:** no row below SEAM; the gate check is on; every REAL row has gaps `none`, apart from those K1 owns.

**Status 2026-11-13: exit met.** Every row is SEAM, PARTIAL or REAL. The gate check is on: `pilot gate` runs the `keywords` gate (selfhost/gate/keyword_gate.pilot; GATE021 no binding, GATE022 verdict below SEAM, GATE023 no rows), read from docs/keyword_matrix.md. Every REAL row whose gaps are not `none` is held by K1 work: an open known bug, or `become`. Left open: generic parameters on a `let` binding are still read and dropped (stdlib facets use them); whether `nameof(x)` must name something declared is for the owner (stdlib quotes undeclared words).

**Honest stop:** a keyword whose fake cannot be removed without breaking corpus programs keeps the fake, as a `SIMULATED` ledger row naming those programs.

### K1: Everyday code gives right answers

**Goal.** The keywords every program uses give the same right answer on all three engines.

**Keywords and what moves them:**
- `for`: honour the step (W1; done 2026-11-13 on every engine, `control/for_range_step`); iterate a `Map` and a `str`. `in`: membership over strings, maps and ranges.
- `fn`: default parameter values (W2; done 2026-11-13 for literal defaults on every engine, `control/fn_param_defaults`; a default that names a parameter or a constant is refused until someone decides where it is evaluated); closures that see later writes to a captured variable, or a diagnostic saying they do not.
- `get`, `set`, `field`, `value`: indexer properties return their value (W3).
- `struct`, `op`: equal records compare equal; a declared `op ==` is called (W4); `static` fields.
- `static`: type-level storage, not just static functions.
- `yield`: one display of an optional on every engine (W5); ledger above DRAFT.
- `type`: generic aliases.
- `sizeof`, `alignof`, `offsetof`: records as well as primitives, from layout descriptors (name-blind).
- `order`, `ascending`, `descending`: `order by` in the `from`/`where` query lowering over sequences. In-memory only; tables are K9.
- `splat`, `pairs`, `flat` (Pairs `*`, `**`, `*..`): operator declarations through `ISplatOperator`, `IPairsOperator` and `IFlattenOperator`.
- `pairs`: structural unpack on all engines (SEED001 and `ir.lower_construct` today).
- `become`: **done 2026-11-13.** A tail call becomes a jump in PilIR (selfhost/ir/lower_tail.pilot), so the interpreter, C, JavaScript and Python all run it in constant stack. Left: a call through a function value, and a `become` with a value to release after the call (`ir.lower_construct`).
- `use`: an aliased module call lowered on PilIR and C.
- `as`: the `as view` family (known bug `seed.view_reinterpret_identity`).
- `ext`: a call on the wrong receiver type is rejected (known bug `check.ext_wrong_receiver`).
- `coalesce`, `with`, `without`: a hidden member is rejected by the checker, not at run time.
- `self`: drop timing matches the registry's promise, or the promise is corrected.
- Rows held back only by an open known bug: `let`, `if`, `return`, `guard`, `catch`. Fix the bug (for example `if_some_foreign_let`, `struct_ok_unwrapped`), move its program into the corpus, and remove its workarounds.

**Exit:** every keyword above at rung 4, or moved to a later phase with its blocker named.

### K2: The checker enforces boundaries

**Goal.** Every visibility and override rule the registry promises is checked, through every path a name can take.

**Keywords:** `priv`, `prot`, `pkg`, `file`, `int`, `pub`, `open`, `lvl`, `override`, `module`, `unit`.

**What moves them:**
- Module-qualified calls obey visibility (W7).
- `prot` reaches derived types and extensions, and nothing else.
- `int` has a boundary (D7).
- `open` permits cross-package overriding and `override` checks it.
- `lvl(N)` clearance with flow-typed elevation (W8, LVL001).
- `module` (D3).
- `unit`: dimension checking, `1s + 64KB` rejected (W6), once D2 settles the meaning.

**Exit:** each keyword at rung 4. Each has an `err_*` program for its main misuse through an unqualified name and through a qualified one.

### K3: Lifecycles, invariants, typestates

**Goal.** Code that runs at scope boundaries runs exactly once, on every exit path, on all engines.

**Keywords:** `scope`, `enter`, `exit` (after D1), `invariant`, `state`, `transition`.

**What moves them:**
- Guards (`0b11`) run their exit last in, first out, including on a failing `?` and on `errdefer` paths.
- `invariant` is checked at every public exit (seam `contracts.invariant`).
- `state` / `transition`: typestate checking in the checker. Static proofs with an SMT solver (M85) go beyond the registry's promise and are not required here.

**Needs:** F7, because owned values must drop exactly once before scope hooks can be trusted.

### K4: Self-generation

**Goal.** Pilot code that writes Pilot code is typed, hygienic and re-checked (Pilot 1.0 goal 2).

**Keywords:** `quote`, `splice` (both registry roles), `unquote` (`~`), `macro`, `call` (`!`), `fields_of`; `splice` covers `!!`. Close any remaining gaps of `syntax`, `comptime` and `type_construct` here too.

**What moves them:**
- `quote` yields `ast<T>`, and spliced code is checked again (M31).
- Hygiene (M27).
- `call f(x)` gives a `CallExpr<T>` value (seam `vm.call_quote`).
- `splice f(~x)` gives `ast<T>`.
- `fields_of` reflects through `comptime` on the IR interpreter (M30).
- `macro` vs `syntax`: one responsibility each, or one becomes the other's Pair.

### K5: Native code and the C ABI

**Goal.** Pilot calls and is called by C natively, and controls allocation (Pilot 1.0 interop is C only).

**Keywords:** `extern`, `lib`, `export`, `frame` (`!&`), `asm`, `assembly`, `noalloc` (block form), `region`.

**What moves them:**
- `extern "C"` declarations call through `pilot.abi` frame plans, and `lib "name"` links (M44).
- `export` emits a C symbol.
- `frame f(x)` builds a `#[repr(C)]` frame (M44).
- `noalloc { .. }` is checked by the M37 verifier.
- `region`, after D8.
- `asm` and `assembly`, after D5 schedules them.

### K6: Adaptation and data-parallel calls

**Keywords:** `adapter`, `each`, `context`.

**What moves them:**
- `adapter A -> B` installs a conversion lowered to inline PilIR (M51, C idioms first).
- `each` vectorises a call over a collection with no intermediate allocation (M40, after D10).
- `context` / `with context` resolves ambient dependencies at compile time.

### K7: Concurrency and choreography

**Goal.** Tasks, locks and channels that really run in parallel, and `.pchor` files that really change layout and topology.

**Keywords:** `async`, `await`, `spawn`, `atomic`, `sync`, `isolate`, `select`, `timeout`, `bounded`, `actor`, `blueprint`, `cue`, `role`, `route`.

**What moves them:**
- OS thread and atomic intrinsics (the small set Rust may still add while contraction is paused; AGENTS.md section 1).
- Structured concurrency (M83).
- `select` over channels.
- `timeout` and `bounded` (after D9).
- `actor` (after D6).
- `cue` enforces the 2-bit cue boundary law (CHOR001).
- `blueprint` applies a layout as an IR pass (M39).
- `role` / `route` place work on threads, processes or hosts (M81).

**Exit test that cannot be faked:** a program whose output depends on two tasks overlapping in time. For example, two tasks that each wait for a message from the other deadlock unless both really run at once.

### K8: Real time

**Keywords:** `deadline`, `within`, `periodic`, `priority`, `jitter`.

**What moves them:**
- A missed deadline is detected and handled (`on_missed` runs only when it is missed).
- `periodic` runs at its period.
- `[Wcet]` proofs (M77).
- Priority and jitter on a scheduler that honours them (M76 for bare metal; an OS real-time class hosted).

**Needs:** K7.

### K9: Data: tables, queries, transactions

**Keywords:** `database`, `transaction`, `commit`, `rollback`, `savepoint`, `connect`, `insert`, `into`, `values`, `update`, `delete`.

**What moves them:**
- `Table<T>` in memory with `insert` / `update` / `delete`.
- `transaction` / `rollback` / `savepoint` really restore state. Share the copy-on-write undo with `plan` (M87) rather than building it twice.
- `database` declares a schema.
- `connect` reaches a real engine through C interop (M44) or `use sql` (M57).

**Exit test that cannot be faked:** rows written inside a transaction that rolls back are gone afterwards, and rows written before it are still there.

### K10: Reactive, differentiable and effect quotes

**Keywords:** `sig` (`!^`), `grad` (`!@`), `plan` (`!?`).

**What moves them:**
- `sig f(x)` builds a glitch-free push-pull node (M86).
- `grad f(x)` gives `Dual<T, G>` with derivatives checked against hand-worked values (M86).
- `plan f(x)` dry-runs effects in a copy-on-write sandbox and commits or discards (M87).

**Needs:** K4 (call-quoting) first.

### K11: Closure

**Goal.** The end state of section 1.

**Work:**
- Regenerate the matrix.
- Every row must read REAL, gaps `none`, ledger `WIRED`.
- Retire the bindings that only existed to report "not implemented yet".
- Make the K0 gate check strict, so that it fails on any row below rung 4.
- Hand the list to the owner for `COMPLETE`.
