# Keyword matrix

The status of every keyword in the registry (`stdlib/core/keywords.pilot`, categories 0–16 and 35–37: 140 entries). AGENTS.md section 11 rule 8 makes this file the place to check before using or describing a keyword, and asks that a keyword's row be updated in the same change that alters it. A row is never marked better than a run shows.

The order in which keywords move up, and what each move needs, is `docs/keyword_roadmap.md`.

Last full check: 2026-11-13, from the keyword audit (`Audit_keywords.md`, 110 probe programs on three engines) and the repository as of that day.

### Complexity rubric

| Score | Meaning | Examples |
|---|---|---|
| 1 | Syntax over constructs that already exist: one rule or one parser branch, no new analysis. | `while`, `else`, `nameof` |
| 2 | One new construct lowered to existing engine operations, or one local checker rule. | `defer`, `requires`, `sizeof` |
| 3 | A new checker analysis (flow, types, patterns, effects) or a new lowering on every engine. | `switch`, `pure`, `become` |
| 4 | New run-time machinery or whole-program analysis: generator frames, arenas, borrow checking, a macro system, foreign calls. | `yield`, `ref`, `extern` |
| 5 | Systems outside a compiler: an async runtime and threads, real-time scheduling, a storage engine, automatic differentiation, a per-target assembler. | `spawn`, `deadline`, `grad` |

### How Pilot / Rust is measured

Code is found from each keyword's search keys. In Rust (`crates/*/src`) these are its seed token (`TokenKind::Kw*`), its receptor (`is_rec(k)`, `(k, sub)` from `stdlib/core/core.pilot`), its modifier act (`ModAct::*`) and its AST node kinds (`NodeKind::*`). In Pilot (`stdlib/`, `selfhost/`, without the registry) they are its node kinds (`nk_*()`), its `nameof(word)` binding and the syntax rules written for it. In both, functions and files whose name contains the keyword or one of its concept words (`switch` and `match`, `requires` and `contract`) as an `_`-separated part also count.

- A hit inside a function with at most two call sites and at most 4,000 characters counts the whole function: a handler written for the keyword.
- A hit inside a larger or widely called function, or one that names three or more different node kinds (a dispatcher or a tree walker), counts only its own line.
- Calls from counted code into such handlers are followed one level.
- Size is characters of code with comments and blank space removed. Characters are used instead of lines because the Rust parser packs several statements per line.

Shared code is counted for every keyword that uses it, so the sizes do not add up to the size of the repository. The share is the useful number: how far a keyword has moved from the Rust seed into Pilot (AGENTS.md section 1, "Pilot first"). A word bound only by a Pilot `syntax` rule shows 100% Pilot even when the seed's generic macro expander does the work in Rust: that expander belongs to no keyword.

The computed columns match words, not meaning: a program named `for_then` counts for `for` and `then`, and a ledger row that describes a keyword without quoting it is missed. Treat them as pointers to check, not as proof. The Pilot tool `tools/keyword_matrix` computes them and writes everything between the two marker comments below; it keeps the hand columns (Bound by, S, I, C, Verdict, Complexity, Notes) as they are written in the tables, and gives a keyword new to the registry a NOT AUDITED row. After editing a hand column, or after a change that adds programs, ledger rows, known bugs or code for a keyword, run `pilot run tools/keyword_matrix/main.pilot` from the repository root. `pilot run tools/keyword_matrix/main.pilot -- --check` exits 1 when this file is stale; `cargo test-full` runs that check (`crates/pilot-cli/tests/cli_keyword_matrix.rs`).
